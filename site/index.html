Local-first / recoverability

The transaction layer between coding agents and Git.

Parallel agents create valuable work before a branch, pull request, or merge queue can explain what happened. Holt relates that in-flight state across Git worktrees, protects what is unique, and makes cleanup recoverable when the evidence is not enough.

The missing layer

Git knows files. Agents need a decision about the whole in-flight set.

Git gives every worktree primitives. Agent fleets add concurrency, partial work, and cleanup pressure. Holt is the local transaction boundary that relates those copies before a destructive action turns uncertainty into lost work.

  1. 01

    Relate

    Compare committed, staged, untracked, ignored, and reachable state across linked worktrees. Advisory overlap and exact destructive evidence stay separate.

  2. 02

    Protect

    Lock a worktree when it holds work found nowhere else. When an instrument fails or a path is unmeasured, the answer is unverifiable—not permission.

  3. 03

    Recover

    Capture or quarantine before cleanup. Rescue and restore keep a named route back; purge remains a separately explicit decision.

Available now

A local safety surface you can inspect on a real repository.

The current launch surface is deliberately local and evidence-led. It is useful today without pretending that every agent host, cloud sandbox, or large-repository shape has the same coverage.

01 / DECISION

Exact gates

status, risk, and gate expose the path, operation, mode, and object evidence behind a destructive decision. Missing evidence holds the action.

02 / ACTION

Reversible cleanup

protect, rescue, clean, quarantines, and restore form a recovery-first loop. Clean is a dry run until explicitly applied.

03 / ACCESS

Agent surfaces

Use the CLI, TUI, project-scoped MCP, and supported host integrations. Coverage is host-specific and visible through holt hosts; it is not a universal hook claim.

04 / BOUNDARY

Offline by default

Repository analysis, local refs, gates, and ordinary operation stay local. Setup actions and package downloads are disclosed separately in the audit trail.

05 / EVIDENCE

Open to re-running

Feature proofs, failure cases, and benchmark contracts are in the repository. Run them against the workflow that matters to you; current comparisons are not presented as traction.

06 / LICENSE

Free core

The single-repository core is available under FSL-1.1-MIT for its defined Permitted Purposes. Read the exact boundary before adopting it.

Know the boundary

Holt should earn trust through the workflow you actually run. These constraints are part of the product surface, not footnotes.

  • Cloud or ephemeral agents do not receive local worktree enforcement by default.
  • Host adapters are project-scoped and contract-tested; named live-host enforcement is a separate proof.
  • Windows agent-host flows, very large repositories, LFS, submodules, and sparse-checkout need your own evaluation.
  • Ignored or unmeasured bytes keep a worktree out of the disposable set rather than becoming a confident guess.

Try the local core

See the decision surface before you change your workflow.

Install from the signed GitHub release path, point Holt at a disposable or real repository, and begin with read-only status. Keep clean --apply as an explicit, reviewable step.

quick start / local repository
$ npm install -g https://github.com/Raed2180416/holt/releases/latest/download/holt.tgz
$ cd your-repo
$ holt status
$ holt protect
$ holt clean --apply # fresh-check, then locked quarantine
