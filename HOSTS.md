# Agent host coverage

holt integrates with AI coding agents three ways, strongest first: a **deterministic blocking hook**, an **MCP server**, or an **advisory rules file** (AGENTS.md). Local Git adds a narrower floor: a content-driven worktree lock covers `git worktree remove --force`, while the pre-commit hook reports risk. Filesystem deletion, explicit unlock, and double-force removal need a configured blocking host hook. This page tracks Holt's own manifest—run `holt hosts` to see the version installed on your machine (the table and cloud caveat below are generated from that manifest).

Every local row uses the same product runtime: Node 22, 24 or 26 and **Git 2.45+**. `holt doctor`
reports the selected Git executable and verifies its `--no-lazy-fetch` capability. An older Git is
a visible prerequisite failure, not a degraded integration; upgrade it from the official
[Git downloads](https://git-scm.com/downloads) before relying on hooks, MCP or CLI analysis.

The table and the cloud-caveat paragraph below are **generated** from `src/integrate/hosts.mjs` by `npm run hosts:generate`. `npm run hosts:check` — wired into CI — fails the build if this file disagrees with what the generator produces. Everything between the `HOLT:HOSTS-TABLE` and `HOLT:CLOUD-CAVEAT` markers below is regenerated — do not hand-edit it, edit the manifest instead and run the generator.

## The cloud caveat

<!-- HOLT:CLOUD-CAVEAT:BEGIN — generated from the CLOUD_CAVEAT export in src/integrate/hosts.mjs. Do not hand-edit between these markers. -->
holt's worktree lock and git pre-commit hook are LOCAL guarantees — they do not apply to cloud/ephemeral agents (Codex cloud, Copilot cloud, Cursor cloud, Google Jules, Replit Agent), which run in a remote sandbox with no local worktree. Repository hook files may be visible there, but holt does not claim blocking unless that sandbox also provisions and runs the holt executable; by default these rows remain advisory. Stated plainly rather than glossed.

## Reading this table

- **BLOCKING** — holt writes the host's documented pre-tool hook and translates explicit denials into that host's refusal channel, without relying on model cooperation. The label names the covered tool scope and failure mode. **Contract-tested, not driven live** means current docs/source plus generated config and payload fixtures were exercised; it is deliberately not presented as a real host-process enforcement run.
- **MCP + advisory (deny hook planned)** — the host *supports* a deny hook, but holt ships MCP + AGENTS.md until its bespoke adapter is verified. A guessed hook format is worse than none.
- **MCP + advisory** — holt runs as an MCP server the agent may call, and its AGENTS.md is read as context.
- **advisory** — the agent only reads a rules file; holt is context, not control. The git floor still applies for any *local* agent.

Some hosts have a mixed posture that a one-line grade cannot carry (the generated table cell is deliberately just the grade — it has to match `strengthLabel()` and what `holt hosts` prints on the terminal, byte for byte, or the two would drift from each other):

- **Claude Code** — `PreToolUse` covers Bash plus the documented Write and Edit contracts. Write and an Edit whose `old_string` equals the current complete file are checked with fresh path/content evidence; ordinary incremental Edit remains silent. MCP tool inputs remain server-defined and are not guessed from argument names. Its model-visible lifecycle brief uses documented `SessionStart` and `UserPromptSubmit` `additionalContext`; Holt intentionally installs no Stop brief because Claude documents Stop `additionalContext` as feedback that continues the conversation under the same loop protections as `decision:"block"`, not as passive context. Re-running `holt integrate` retires Holt's former Stop entry while preserving other Stop hooks. See [Claude's current hook reference](https://code.claude.com/docs/en/hooks).
- **Cursor** — the shell guard remains fail-open on hook failure. Separately, Cursor's documented Stop output is `followup_message`, which starts another agent loop; Holt emits it only for `status:"completed"`, `loop_count:0`, and changed actionable state. The resulting loop is ineligible, so the follow-up cannot perpetuate itself. This is contract-tested, not a claimed live Cursor-host run. See [Cursor's official example](https://cursor.com/blog/agent-best-practices#example-long-running-agent-loop).
- **OpenCode** — the stable plugin's `tool.execute.before` is the shell guard. Its `session.created` event plus `console.log` is terminal/UI output, not model context, so Holt no longer emits or describes that as injection. Proactive orientation remains AGENTS.md plus model-invoked MCP until a stable consumable context hook is proven. [OpenCode V2](https://opencode.ai/v2/docs/build/plugins) has a real pre-dispatch context hook, but its plugin API is explicitly beta and structurally different, so Holt does not splice it into the stable 1.x adapter. `opencode debug config` proves only plugin discovery, not a live destructive-call refusal. See the [stable OpenCode plugin API](https://dev.opencode.ai/docs/plugins/).
- **OpenAI Codex local clients** — project `PreToolUse` covers Bash plus exact operations in Codex's documented `apply_patch` command grammar. Delete File and a move that would replace an existing destination reach fresh evidence; ordinary Add/Update stays silent. Codex does not support an ask decision, so uncertainty on a covered destructive operation maps to deny rather than an unsupported response that lets the tool continue. Local-function and MCP inputs stay outside this boundary until their tool-specific contracts are wired. Separately, Holt installs the documented `SessionStart` and `UserPromptSubmit` lifecycle hooks so sibling context arrives without waiting for an MCP call; session start auto-protects before the first tool, and an unchanged per-prompt brief is suppressed. Project hooks are skipped until their exact definition is reviewed and trusted in `/hooks`. This is contract-tested configuration, not a claimed live Codex-host run. See the current [Codex hook documentation](https://learn.chatgpt.com/docs/hooks).
- **Goose (Block)** — holt now installs a project plugin under `.agents/plugins/holt` for deterministic shell-command denials. Goose's MCP config is still YAML in the user's main config beside permissions and secrets, so holt does not rewrite it; the hook is blocking while MCP remains unsupported.
- **Aider** — has no MCP client as of 2026-08-01 (confirmed against Aider's current docs), and nothing is read automatically, not even AGENTS.md. Its coverage here is the local Git lock/pre-commit floor plus a `CONVENTIONS.md` the user loads explicitly (`--read` or `.aider.conf.yml`'s `read:`).

Full per-host detail, including every `note` above, is available from `holt hosts --json`.

Once configured in a real local checkout, the **git worktree lock** (agent-independent) and the
**git pre-commit hook** remain the local floor. Neither exists in a repository where Holt has not
installed or applied it.
